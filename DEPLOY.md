# Деплой нової версії

Порядок має значення: кроки 1–3 роблять сайт юридично придатним приймати
гроші, 4–6 піднімають його, 7 вмикає оплати. Пропустити середину не можна —
кожен наступний крок спирається на попередній.

Чому саме так зроблено — у `CLAUDE.md`. Тут тільки послідовність дій.

## 0. Перед початком: секрети

**Це треба зробити один раз, і краще до деплою.**

`backend/.env` лежить у git разом із `SECRET_KEY`, паролем бази й паролем
адміна. Крім того, `.env.example` колись був побайтовою копією `.env`
із бойовими ключами monobank — і `.gitignore` його явно дозволяє.

```bash
git rm --cached backend/.env
echo "backend/.env" >> .gitignore
git commit -m "прибрати .env з індексу"
```

Після цього **провернути** все, що там лежало: `SECRET_KEY`, пароль
Postgres, пароль адмінки, ключі monobank. Старі значення назавжди
лишаються в історії git — видалення файлу їх не стирає.

## 2. Ключі monobank у `backend/.env`

За зразком `.env.example`. Уважно: це **два різні продукти**.

| Змінна | Де брати в кабінеті |
|---|---|
| `MONO_CHAST_STORE_ID`, `MONO_CHAST_SIGN_KEY` | розділ «Покупка Частинами» |
| `MONO_PLATA_TOKEN` | «Розробникам → plata by mono» |

`MONO_PLATA_TOKEN` зараз порожній — без нього картковий фолбек не працює,
а він обов'язковий: `CLIENT_NOT_FOUND` від ПЧ буде регулярним станом.

## ⚠ Перед підйомом на проді: пароль бази

`docker-compose.yml` більше не хардкодить облікові дані — сервіс `db` бере їх
із `backend/.env`. Але **том із базою на проді вже створений** зі старими
значеннями (`postgres` / `2111` / `prime_platform_db`).

`POSTGRES_PASSWORD` і `POSTGRES_DB` впливають **тільки на перший запуск**
порожнього тому. На вже існуючій базі вони не міняють нічого: пароль
усередині Postgres лишається старим.

Тому в прод-`.env` ці три значення мають **збігатися з тим, що в базі зараз**:

```
POSTGRES_USER=postgres
POSTGRES_PASSWORD=<той, що вже в базі>
POSTGRES_DB=prime_platform_db
DATABASE_URL=postgresql+asyncpg://postgres:<той самий>@db:5432/prime_platform_db
```

Якщо вписати новий пароль, backend упаде з `password authentication failed`,
а виглядатиме це як проблема мережі.

**Щоб справді змінити пароль бази** — спершу підняти старий контейнер і
виконати `ALTER USER postgres WITH PASSWORD '...';`, і лише потім правити `.env`.

## 3. Збірка й підйом

```bash
git pull
docker compose build --no-cache backend nginx
docker compose up -d
```

`--no-cache` для backend потрібен цього разу: у `Dockerfile` додано
`fonts-dejavu-core` (кирилиця в PDF сертифікатів) і нові пакети
`reportlab` / `qrcode` у `requirements.txt`.

## 4. Міграції

```bash
docker compose exec backend alembic upgrade head
```

Чекають **0003…0007**:

| Міграція | Що робить |
|---|---|
| 0003 | таблиці `orders` і `payments` |
| 0004 | сертифікати: новий номер, `kind`, прогрес рівнів (тільки ALTER) |
| 0005 | `page_visits` — власний лічильник |
| 0006 | `packages.validity_days` — термін дії |
| 0007 | знижки в замовленні |

0004 **не перестворює таблицю** — сертифікати, які вже на руках у людей,
продовжать перевірятися.

Перевірити, що доїхало:

```bash
docker compose exec backend alembic current
```

## 6. Перевірка живого сайту

Пройти руками, це швидше за будь-який тест:

- [ ] `/` — головна, працює експрес-тест із трьох питань
- [ ] `/level-test` — розвилка, 25 питань, кнопка «Назад», форма в кінці
- [ ] `/packages` — ціни з нової сітки, на картках видно «Діє N днів»
- [ ] `/verify-certificate?code=` — старий номер Наталії досі знаходиться
- [ ] `/about` — шкала CEFR і блок сертифіката на місці
- [ ] `/offer` — реквізити підставилися, попередження зникло
- [ ] `/admin` — вхід, дашборд, заявки, замовлення, сертифікати
- [ ] Видати тестовий сертифікат → «Зробити PDF» → відкрити → **відсканувати
      QR телефоном** і переконатися, що сторінка перевірки відкривається
- [ ] Відкрити `/level-test` **прямим посиланням** (не переходом) — перевірка
      SPA-фолбеку в nginx
- [ ] Подивитись сайт із телефона: основний трафік іде з Instagram

**Статистика.** Зайти на дашборд наступного дня й глянути унікальних
відвідувачів. Якщо їх підозріло мало — перевірити, що `X-Forwarded-For`
доходить до бекенда (див. `app/core/clientip.py`).

## 7. Оплати — вмикати ОСТАННІМИ

Спочатку пісочниця, наскрізь:

```
https://u2-demo-ext.mono.st4g3.com
store: test_store_with_confirm
key:   secret_98765432--123-123
```

Прогнати повний сценарій: створення замовлення → ПЧ → колбек →
`GET /api/orders/{id}/state` → підтвердження. Окремо перевірити
`CLIENT_NOT_FOUND`: людина має **мовчки** потрапити на картковий платіж,
без повідомлення про помилку.

І лише потім у конфізі:

```python
payments_enabled = True
```

Вимикач саме в конфізі, щоб вимкнути оплати без релізу, якщо щось піде не так.

## Що лишається відкритим

- **Питання до підтримки monobank:** таблиця комісій за кількістю частин
  (публічно тільки «від 2,9%») і чи можливе часткове повернення.
- **Версії в `requirements.txt` не зафіксовані** — через це вже ламався
  bcrypt при пересборці. Варто перейти на lock-файл.
- **Відгуки й галерея викладачів** — повернути, коли буде 5–8 реальних
  відгуків і 4+ живих профілі. Вигаданих не додавати: це заборонена
  оманлива практика й порушення правил Google Ads і Meta.
- **Сертифікат Let's Encrypt** — автопродовження й reload nginx уже
  налаштовані, найближче продовження близько 23 грудня 2026.
  Після цієї дати варто разово перевірити логи certbot.
