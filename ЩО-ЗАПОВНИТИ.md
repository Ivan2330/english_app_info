# Що заповнити перед запуском оплат

Коротко: **сайт можна заливати вже зараз**. Все нижче стосується тільки
прийому грошей — до того сайт працює як інформаційний, заявки збираються.

Послідовність деплою — у `DEPLOY.md`. Тут тільки те, що вписуєте ви.

---

## 1. Безпека — зробити ПЕРШИМ

`backend/.env` досі лежить у git разом із `SECRET_KEY`, паролем бази
й паролем адмінки.

```bash
cd english_app_info
git rm --cached backend/.env
echo "backend/.env" >> .gitignore
git commit -m "прибрати .env з індексу"
```

**Після цього провернути все, що там було.** Видалення файлу не стирає
його з історії git — старі значення лишаються назавжди і їх видно кожному,
хто має доступ до репозиторію:

| Що провернути | Як |
|---|---|
| `SECRET_KEY` | `python -c "import secrets; print(secrets.token_urlsafe(48))"` |
| `POSTGRES_PASSWORD` | новий пароль + оновити `DATABASE_URL` |
| `ADMIN_PASSWORD` | новий пароль адмінки |
| `MONO_CHAST_SIGN_KEY` | перевипустити в кабінеті monobank |

> Зміна `SECRET_KEY` обнулить статистику унікальних відвідувачів: він бере
> участь у хешуванні візитів. Це нормально, просто знайте заздалегідь.

## 2. Ключі monobank → `backend/.env`

Два **різні** продукти й **різні** ключі. Це найчастіша плутанина.

### Покупка Частинами

Бізнес-кабінет monobank → розділ **«Покупка Частинами»**.
За вашими словами, ці ключі вже видані.

```
MONO_CHAST_STORE_ID=<store id>
MONO_CHAST_SIGN_KEY=<sign key>
```

### plata by mono — картковий еквайринг

Бізнес-кабінет monobank → **Розробникам → plata by mono → API-токен**.
Зараз порожній.

```
MONO_PLATA_TOKEN=<токен>
```

**Цей токен обовʼязковий.** Покупка Частинами працює тільки для клієнтів
monobank; для решти банк повертає `CLIENT_NOT_FOUND`, і замовлення мовчки
йде на картковий платіж. Без токена ця гілка обірветься.

### Поки тестуєте

Для пісочниці підставити замість бойових:

```
MONO_CHAST_BASE_URL=https://u2-demo-ext.mono.st4g3.com
MONO_CHAST_STORE_ID=test_store_with_confirm
MONO_CHAST_SIGN_KEY=secret_98765432--123-123
```

Для бою повернути `MONO_CHAST_BASE_URL` на бойову адресу з документації
monobank і свої ключі.

## 3. Увімкнути оплати — ОСТАННІМ

```
PAYMENTS_ENABLED=false
```

Ставити `true` **тільки після** того, як у пісочниці пройшов повний
сценарій: замовлення → ПЧ → колбек → підтвердження, і окремо перевірено,
що `CLIENT_NOT_FOUND` мовчки переводить людину на картку без повідомлення
про помилку.

Поки `false` — ендпоінт оплати віддає 503 і пропонує оформити вручну.
Вимикач у конфізі саме для того, щоб вимкнути оплати без релізу,
якщо щось піде не так.

**Рядок про ліцензію CC BY 4.0 у футері має лишитися в будь-якому разі** —
це умова використання шрифта, а не прикраса.

## Два питання до підтримки monobank

Поставити до запуску оплат, обидва впливають на тексти на сайті:

1. **Таблиця комісій за кількістю частин.** Публічно вказано лише
   «від 2,9%». Нам треба точні цифри, щоб порахувати, на яких пакетах
   маржа витримує 3 платежі, а на яких ПЧ краще вимкнути.
   Націнювати не можна — за це відключають від сервісу.

2. **Чи можливе часткове повернення і як оформлюється.** У нас повернення
   за невикористані уроки — штатна операція, вона описана в оферті.
   Треба розуміти, як вона проходить через ПЧ.
